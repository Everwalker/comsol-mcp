# Windows owned Job limits v3

Status: IMPLEMENTED_UNVERIFIED. Software controls use actual production classes with synthetic SDK returns. Native Windows is NOT_RUN; the native policy issuer remains absent and cannot authorize Resume. This is not W26, T037, hard-quota, full-goal or whole-host isolation acceptance.

The pinned private startup loader accepts a new closed wrapper `comsol-mcp.windows-t037-profile/3` with exactly `schema`, `host_resource_profile`, and `job_limits`. The embedded shared HostResourceProfile stays byte/schema compatible. The old v1/v2 wrappers do not accept limits and are not implicitly upgraded. Internally v3 reuses WindowsT037ProfileV2 with an explicit wrapper_schema and typed JobLimitsV1; safe metadata reports v3, all selected targets, source SHA, composite profile SHA and targets SHA. Old v2 safe metadata and SHA remain unchanged.

`job_limits` uses schema `comsol-mcp.windows-job-limits/1`, with three explicit positive integers: process_memory_limit_bytes, job_memory_limit_bytes, active_process_limit. No default cap is supplied. Memory values fit Win64 SIZE_T, active count fits DWORD; booleans/floats/null/unknown keys are rejected, and process cap cannot exceed Job cap. These are committed virtual-memory caps, not RSS/working-set limits. Active count covers simultaneously associated processes, not solver CPU cores or scheduler case budgets. No CPU-rate or process/Job time limit is added, preserving execution_timeout=null.

The original _Win32LaunchApi creates only one unnamed fresh Job. Before SetInformation it registers the exact acquisition, profile and original CloseHandle with the existing NativeOwnedRegistry, serializes acquisition with that registry lock, verifies an empty zero-state Job, applies only ACTIVE_PROCESS|PROCESS_MEMORY|JOB_MEMORY (0x308), then queries exact flags/values and full empty membership. No kill-on-close, breakaway, working-set, priority, affinity or time-limit flags are allowed. Actual configured Job and source/profile/target fingerprints must match on every child entry, immediately before CreateProcess, before assignment and at the future Resume boundary. Capacity exhaustion refuses before birth; Microsoft documents that an over-limit assignment may terminate the new process.

Missing/v1/v2/null targets are JOB_LIMITS_NOT_CONFIGURED at create/direct-child interfaces; the current public factory's unavailable native-policy preflight may refuse even earlier. Invalid SDK HANDLE/BOOL, lengths, values, flags, membership, owner or profile never report configuration success. Query drift is sticky UNKNOWN. No retry changes limits, creates a replacement child or resumes. The original factory/controller/store and retained child remain the only owners. Explicit Job close requires empty native membership, no ancillary owned resources and confirmed retained child exits; failed/malformed CloseHandle retains the original entry and captured closer. Original authorized registry retry is explicit cleanup, not reconfiguration. Metadata cannot supply an acquisition or resume issuer.

Windows ABI support is deliberately limited to checked Win64 layout (BASIC 64 bytes, EXTENDED 144, ProcessMemoryLimit offset 112) using fixed 32/64-bit integers and SIZE_T. Native Windows ABI, committed-limit violations, concurrency behavior, COMSOL/JDK/license compatibility, AppContainer/SCM/WFP/default-block/arbitration, real host grants, loaded image/argv/MIC/whole-tree policy proof and disk hard quota remain unverified. Unconfigured native dispatcher still refuses before child creation.

## R13 original release-path correction

Independent R12 source/software review reproduced one P2: ordinary close refused a live UNKNOWN child, but original NativeOwnedRegistry.retry_owned bypassed the outer close predicate, called captured CloseHandle and enabled the RELEASED reconciliation shortcut. Original R12 source, repro, failed controls and immutable review receipt remain unchanged. R12 was not accepted.

R13 moves the required release predicates into the original captured Job closer. Every original registry retry/release/drain and captured-closer call checks the same exact acquired HANDLE scalar, actual original entry/adapter/registry owner and active acquisition, empty native whole-Job membership, absent ancillary native ownership and confirmed terminal original retained children before the captured original SDK callback. The original registry RLock covers predicate reads and native close. No generic registry protocol or other resource family changes. Unknown/malformed/gate failures retain ownership and preserve the first close cause; they do not call CloseHandle. Configuration FAILED/UNKNOWN can still be explicitly cleaned up after real empty/terminal proof. Only genuinely confirmed original CloseHandle permits RELEASED shortcut reconciliation without querying a closed HANDLE. This changes cleanup safety, not limits, issuer authority, native acceptance or the original goal scope.
