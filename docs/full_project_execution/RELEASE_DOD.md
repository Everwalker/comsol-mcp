# 全量完成的判定，不新增产品范围

这是原26工作包/272动作/60测试与W26交付的索引，不是第二套测试合同。具体case仍以原03_ACCEPTANCE及冻结基准为准。

全量完成需同时满足：
- 26工作包的必需交付均实现并有适用证据，W21/W22旧批准可在有理据情况下继承；
- 全部原逻辑动作有明确实现路径和错误/权限/类型契约；不存在只登记名字或通用Java口号顶替语义的条目；
- 原60测试的每个适用平台版本目标完成，真实不适用必须有原合同依据；缺机器/许可/权限不是N/A；
- 三领域从输入→计算→结果→图像→报告→保存/新路径重放齐全；数值验证和物理校准边界如实；
- 六组合和3架构构件、离线/源码恢复、升级回退、安全/秘密扫描、schema与文档一致；
- 最终代码、依赖、配置、产物和证据来源一致，独立Reviewer对最终候选APPROVED；
- 清理仅本次所有资源，已授权正常同步得到真实远端SHA；同步阻塞不能说已发布。

软件测试通过总数不是完成判据；注册操作数不是执行能力；hash只证明字节；mock不是native；目录存在不是可恢复。全量原要求尚有必需未验证时，工具可总结缺口但不得用APPROVED_SCOPE代替PROJECT_ACCEPTED。

状态工具仅检查清单完整性、类型与结论引用，不具备原生真实性/物理正确性证明能力。Reviewer和实际运行才是验收过程。
