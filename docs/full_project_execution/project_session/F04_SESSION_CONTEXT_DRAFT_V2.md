# F04 session-context prototype revision 2

Status: **isolated draft only**. The reviewed v1 capsule remains unchanged at `f04_draft_runs/run_20260927T063636Z`. This revision addresses the review findings about shallow dataclass immutability, user-controlled path components, and endpoint aliases. It changes no production runtime source and makes no COMSOL/native acceptance claim.

## Corrections

- `SessionRuntimeConfig.classpath` must be an actual non-empty tuple of `Path` objects. Runtime installation, Java, preferences, and session-state roots must also be `Path` objects. The frozen config and tuple prevent later caller mutation from changing Worker build/runtime inputs.
- Endpoint evidence and Worker connection epoch are separate fields in frozen `SessionEndpointIdentity`. `worker_epoch` invalidates Java object handles and never serves as a server lock identity. Scheduling requires the actual TCP peer address and port observed after connection; requested DNS spelling is never itself a lane. An exact local owned-process PID/birth/executable record plus listener-socket evidence adds a stable process lock shared across Worker epochs and listener aliases. These verified owned lanes may overlap only when their process/socket evidence is disjoint. Shared/unowned or incomplete process identity uses the same global exclusive gate as all owned lanes, so uncertainty cannot run concurrently with a known server. This deliberately sacrifices parallelism when distinct server identity cannot be proven.
- Session state paths never interpolate caller project/session IDs. A SHA-256 key over both IDs forms the path component, and the resolved path must remain below the configured state root. Equal session IDs in different projects therefore remain separate. A symlink escape fails closed.

The process-backed lane is valid only when a trusted host-side adapter produced the exact process birth and listener-socket evidence. The prototype's dataclasses and synthetic test fixtures are not such proof and cannot be treated as trusted user input. Each proven process birth gets its own single-worker FIFO executor, so same-server jobs retain submission order and a long queue on one server does not occupy threads assigned to another server. Unknown work has one exclusive FIFO lane coordinated by the same read/write gate: it waits for known work and blocks all known lanes while running. `close()` first prevents further submission, then drains every accepted lane under that gate. The same global scheduler registry must be owned by the daemon and injected into every session context; creating another backend cannot create a second lock domain. A production implementation must obtain actual socket peer evidence from the Worker connection and process/listener evidence through the approved host adapter. If process evidence is unavailable, use the global exclusive lane rather than infer identity from a Worker epoch or requested hostname.

## Evidence boundary

`f04_draft_v2/session_context.py` is a reference model, not wired into `comsol_mcp`. Its tests exercise immutable classpath and endpoint evidence, safe path derivation, refusal without an observed peer socket, aliases tied to actual peer/process evidence, unknown-versus-owned exclusion, same-PID multi-socket serialization, same-server FIFO order, a busy-lane backlog not starving a distinct server, close/submit races, callbacks, per-context state, and actual overlap across different proven owned process births. Catalog/session-rule tests are carried forward to detect accidental contract drift. The process identities used by tests are synthetic controls, not host observations. The run receipt reports this prototype suite separately from all product and native claims.
