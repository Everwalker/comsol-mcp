# F04 session lifecycle integration draft

Status: **DRAFT / NO PRODUCTION ROUTE IMPLEMENTED**. This design and its isolated reference-model tests are outside `comsol_mcp`; they do not close the nine catalog actions or establish COMSOL runtime acceptance. The frozen contract and exact schemas are in `evidence/main_f04_session_next_execution_unit.json` and `contract/02_ACTION_CATALOG.json`.

## Current source boundary

The canonical catalog defines nine project-scoped actions. `session.list`, `session.inspect`, and `session.health` are reads; `session.connect`, `session.disconnect`, `session.reconnect`, and `session.recover` are state writes; `session.start` and `session.stop` are host-control actions. All nine are still `PROPOSED_NOT_IMPLEMENTED`. Their existing schemas remain authoritative; this unit does not add policy vocabulary or optional fields.

Current session-related persistence already exists, but its semantics are narrower than F04. `OperationStore` has a `sessions` metadata table keyed by `session_id`. `_runtime_state.save_runtime_state` writes a complete ledger snapshot to that key; the record contains a worker identity and connection epoch, server-instance ID, permissions, model generations, model state, and active tickets. On restore, changed Worker identity/epoch invalidates old ModelRefs and active tickets are reported as `UNKNOWN`. The write currently replaces the whole session metadata value, so lifecycle metadata must be added as a separate nested field and merged on each ledger save; a second session truth table is not needed.

`ManagedBackend` currently owns one `worker`, one `service`, and one active worker identity. A connection replaces that handle and restores the ledger for its endpoint-derived session ID. It cannot represent the original requirement for separate COMSOL 6.3/6.4 Workers and budgeted parallel servers by assigning a second endpoint to the existing fields. Final acceptance requires session-keyed handles and independent endpoint queues; a single-active-session refusal is only a transitional fail-safe, not completion. Silent takeover is not acceptable.

The existing legacy `server_start` is not a proven F04 launcher. It acts on the legacy local COMSOL/MPh state and does not produce a dedicated session's durable PID/birth/runtime/endpoint identity. `session.start` therefore needs a runtime-specific launcher and post-start identity verification before it can report an owned session. Until that exists, it must refuse as not implemented rather than route through the legacy helper.

## Shared-global inventory and parallel isolation choice

The exact current module-global access path is broader than the two assignments in `ManagedBackend.connect`:

| Source | Shared state touched by a managed request | Parallel-session risk |
|---|---|---|
| `_server.py` | `_server`, `_client`, `_remote_client_factory`, `_client_connected`, `_connected_host`, `_connected_port`, `_current_model`, `_current_model_origin`, `_current_model_path`, `_server_started_by_mcp`, `_mcp_owned_model_tags`, `_last_command`, `_last_error`; `_runtime_lock`; `_background_jobs` and its lock; process-wide runtime/home/endpoint defaults. | A second connect overwrites the first client/model/ownership context. Global jobs, lock, and runtime constants are shared. |
| `_managed_backend.py` | `connect` sets `_remote_client_factory`, `_client`, `_client_connected`, endpoint and ownership flags; `adopt` reads `_mcp_owned_model_tags` and calls `_set_current_model`; legacy selection reads `_current_model`. The backend itself has one `worker`, `service`, and `worker_identity`. | Worker/ledger replacement and model adoption can cross session identity; parallel servers have no independent service handles. |
| `_connection.py` | Reads/writes the global client/factory, endpoint, current model and path, ownership tags, server handle and started flag; its shutdown path can stop the global server. | One session disconnect can clear or stop another session's client/server. |
| `_model.py`, `_tools_model.py` | Read/write `_current_model`, model origin/path, `_mcp_owned_model_tags`, and enumerate the process-global client. | Model selection, adoption and pruning can use the wrong endpoint or ownership set. |
| `_tools_connection.py` | Starts/connects/stops the global legacy server/client; reads global endpoint/ownership state. It uses process-wide `COMSOL_ROOT`, default version, host, port, and timeout. | This path is not scoped to an F04 runtime and must not implement `session.start/connect/stop`. |
| `_state.py` | Reads session globals to publish status; updates global last-command/error; shares background-job objects and lock. `WORKFLOW_FILE`, `STATUS_FILE`, `OUTPUTS_DIR`, `OPERATIONS_FILE`, and related paths are imported once from `_server.py`. | Status, workflow, output, log, and async-job state may bleed across projects or runtimes. |
| `_tools_workflow.py`, `_tools_snapshot.py` | Use global current model and import process-wide paths/default endpoints for workflow files, outputs, logs, and snapshots. | Runtime/project paths may be mixed even if Worker objects are separate. |
| `_tools_solver.py` | Background solve acquires global `_runtime_lock`. | One endpoint blocks unrelated sessions; changing the lock to parallel requires per-endpoint serialization, not no locking. |

Root-approved implementation boundary: a `SessionRuntimeContext` per persisted session, selected by the outer `execution.session_id` inside a context manager, with no temporary environment or global-value swapping. Refactor all listed state reads/writes to an explicit context accessor; move paths, runtime installation, Worker/service identity, model selection, owned tags, async jobs, and locks into that context. `SessionRuntimeConfig` must be immutable for each Worker lifetime, including exact COMSOL version and classpath. Managed lookup without a context fails closed; any legacy default context must be explicitly selected. Use one serial execution queue per canonical server endpoint, so aliases such as `localhost` and `127.0.0.1` cannot bypass same-server serialization while separate 6.3 and 6.4 endpoint queues can run concurrently. Propagate the context into queue threads/callbacks explicitly with `contextvars.copy_context()` or a typed task envelope; thread-pool submission does not reliably inherit ambient context automatically. Keep every mutable model/job/ownership/workflow container per context. Keep one durable `OperationStore`/ProjectAuthority source of truth and use its existing transaction lock; never change process environment to select a runtime.

This is a large but bounded refactor because it touches the access modules above. It avoids a new Python-executor IPC protocol and a second persistence authority. The process-boundary alternative would isolate all legacy globals naturally and is stronger against missed call sites, but requires a parent/child command and event protocol, exact child plus Worker/server lifecycle cleanup, and a deliberate way to persist `ExecutionService` ledger changes through the single operation store. Do not claim the prototype tests complete the refactor: before implementation, add an access inventory test/static guard that prevents new direct process-global runtime reads from managed-session code, then add barrier-based production A/B tests using distinct fake 6.3/6.4 contexts and paths.

## State and authority rules

Persist one lifecycle record inside the existing `sessions` metadata value, separate from the nested runtime-ledger snapshot. The lifecycle record binds `project_id`, `session_id`, `runtime_id`, canonical endpoint, client state, server ownership, Worker instance/epoch, server instance, exact owned-process identity when applicable, and timestamps/source for health observations. Persist request and idempotency identities through the existing operation/job store. `credentials_ref` is resolved only by an approved host-side provider and is never copied raw to durable metadata or logs.

Project scoping is checked through F03 `ProjectAuthority` for every inspect or mutation. A connected endpoint is not owned merely because the Worker can attach or its PID can be observed. `session.connect` records a shared/external attachment unless trusted process-launch evidence already proves MCP ownership. The F03 host permission ceiling and project grant intersection apply to `HOST_CONTROL`; an audit reference is hashed and does not grant permission by itself.

An MCP-started server is stoppable only when the persisted server ownership is `mcp_managed`, the operation is currently authorized, no active or unknown requests remain, and a fresh pre-termination process observation exactly matches the recorded PID, birth identity, executable, runtime, and endpoint. After signaling that exact target, `STOPPED` requires both a complete exact-PID inventory proving the original birth identity is absent and a complete endpoint-listener query with no listener remaining. Incomplete process/listener checks or a still-bound endpoint remain `UNKNOWN`; PID reuse cannot authorize signaling the replacement process. A PID by itself, process name, endpoint alone, or client disconnect is insufficient. A shared or user-owned server remains non-stoppable through the current contract unless an independently trusted ownership proof and explicitly authorized path are available.

Client state and server state remain separate. `session.disconnect` closes only this Worker/client connection; it neither signals nor terminates the server. Reconnect increments the Worker epoch and invalidates all old Java object handles/ModelRefs. Existing `UNKNOWN` requests remain attached to their original request IDs and are queried, never replayed. An ambiguous launch records `UNKNOWN`; another launch requires exact reconciliation that the previous owned process is absent.

`session.list`, `session.inspect`, and busy-queue `session.health` are nonblocking control-plane reads from a durable/cached snapshot. They must not queue behind a solve or report stale cache data as live health. A fresh probe may be attempted only when the relevant Worker is available; missing or stale evidence stays `UNKNOWN`/`STALE`.

## Contract-to-implementation map

| Action | Required route and state transition | Refusal / truthful result |
|---|---|---|
| `session.list` | Read only sessions visible to `project_id`; include active, disconnected/lost, unknown, and stopped states from durable metadata. | Missing project scope or malformed persisted record fails closed; no runtime scan is implied by cached listing. |
| `session.connect` | Validate installed `runtime_id`, endpoint, credentials reference, then attach and verify actual runtime/server identity. Persist an external/shared attachment. | Any runtime/version/endpoint uncertainty returns `UNKNOWN` or an explicit capability refusal; never marks the server MCP-owned. |
| `session.start` | Require intersected `host_control`; create a dedicated server, then bind actual PID/birth/executable/runtime/endpoint and Worker identity before returning success. Idempotency is durable. | Launch timeout/partial identity becomes `UNKNOWN`; no automatic second launch or retry until reconciliation. |
| `session.inspect` | Read project-bound durable identity, ownership, Worker epoch, server identity, and last health evidence. | Foreign project, schema-invalid record, or absent identity fails closed; no inferred ownership. |
| `session.reconnect` | Reattach only to the same verified runtime/endpoint/server identity; create a new Worker epoch and invalidate old refs. | Never replay unknown calls; foreign server identity or unresolved dispatch refuses/returns `UNKNOWN`. |
| `session.disconnect` | After active request reconciliation, disconnect this client only. Preserve independent server ownership/process identity. | Active/unknown operations block disconnect; never translates to server shutdown. |
| `session.stop` | Require `host_control`, valid audit-reference handling, MCP-owned server record, exact fresh process identity, and no active/unknown request. | Shared/unowned server, PID reuse, incomplete process inventory, or unresolved jobs refuses or remains `UNKNOWN`; no kill-by-name. |
| `session.health` | Return a fresh lightweight observation only when it cannot block behind engine work; otherwise return clearly marked cached/stale state. | Do not map timeout or missing process evidence to healthy/stopped. |
| `session.recover` | Query original Worker request IDs; update only on authoritative status evidence. Invalidate stale refs on epoch change. | No replay of unknown mutation, solve, or launch. Incomplete reconciliation remains `UNKNOWN`. |

## Integration sequence after the current shared-source hold

1. Add isolated migration/restart tests proving the `sessions` metadata merge preserves both runtime-ledger and lifecycle namespaces across every save and restore. Preserve legacy records as `UNATTRIBUTED`/unknown; do not guess project or ownership.
2. Implement the session-keyed Worker/ExecutionService handle boundary. Every managed action must select by outer `execution.session_id`; queue/lock by canonical server endpoint, not model or project; control reads may use immutable snapshots only. Single-active refusal is a transitional fail-safe and cannot close F04.
3. Implement the injected process adapter behind a platform/runtime contract: launch returns PID plus stable birth/executable/runtime/endpoint evidence; query/terminate always revalidate that complete identity. Unsupported platform launch capabilities fail closed.
4. Route and validate the nine catalog operations through the canonical dispatcher. Bind idempotency to project, operation, runtime, endpoint, and semantic body; retain the existing direct/nested wrapper normalization from F03.
5. Run restart, duplicate-key, changed-body/project, foreign-session, forged-ownership, PID reuse, active/unknown refusal, disconnect-preserves-server, reconnect-invalidates-handle, and no-unknown-replay tests. Then acquire a separately frozen native lifecycle slot; synthetic process adapters are software tests only.
