# W20批准后：执行原W21的通用范围

原始依据见contract/W21_SOURCE_EXCERPT.md。本文件是本用户任务对下一工作包的固定执行范围，不是本次新审计结论。

## 何时开始
W20冻结要求已满足且独立Reviewer签署当前候选。随后主Agent直接继续；原计划W17/W19依赖按已验收范围复用，不要求把所有历史取消、GUI或六组合重新认证。W21新改动造成已确认W20回归时，仅修复相关回归，不重新扩审全仓。

## 本轮五项固定交付
1. **参数case与扫描。**按现有API与任务入口支持参数值/单位、case ID、状态、原始结果、inner/outer/time正确对应；至少一个两参数＋瞬态的小型真实扫描，保留参数索引表。复用W19作业，不另造任务后端。
2. **预算和复用。**限制允许的case/计算预算，失败case明确记录；支持已有结果缓存或续跑，输入/模型/求解配置/版本变化后不误用缓存，同请求不重复派发。不是跨平台任意作业恢复的完整认证。
3. **有限优化。**在固定参数范围、目标和约束下完成一个小型真实优化流程，返回验证过的候选及其原始结果。算法由Agent依据现有实现选择，不要求引入新的优化框架或证明全局最优；预算耗尽时准确报告当前最佳可行解或未找到可行解。
4. **通用阶段状态传递。**至少一个小型多阶段模型，把前一阶段实际状态映射到后一阶段初始/参考状态，记录变量、单位、时刻、选区和checkpoint，不默默重置历史。它验证原T047的传递子项；完整有台/无台胶形、UV固化化学和应力领域验收保留在W24，原T047总项不得因此标完全PASS。
5. **同源双版本交付。**Windows6.3和6.4各自运行上述通用流程并保存/读取结果；沿用W20验证器对选定case、约束与状态传递做检查，记录代码/模型/结果对应。保留Mac兼容，不要求没有资源的其他组合先跑完。

这些五项就是当前W21通过标准，不再每轮扩成新功能目录。Reviewer可以设计必要反例验证这五项，但不能添加高级算法、更多业务物理场、全套GUI、任意规模性能目标或新的审批系统。

## 执行和验收方式
先盘点已有实现，复用已完成case/cache/作业与通用Java代码路径，不复制一套W21业务。用小而有独立参考的模型，不拿用户正在工作的模型作破坏性测试。参数/目标/预算/容差在该运行开始前确定，不能看结果后改变要求；需要模型或许可超出本机能力时明确相应阻塞。

对应原T021完整验证参数/time映射；原T047只登记明确的通用传递子项，完整领域状态留NOT_RUN/PARTIAL并指向W24。这不是删除旧验收，而是避免把后续领域包前移或把子项成果夸大。

Reviewer复测：错参数索引、旧缓存、超预算重复执行、失败case被当最优、状态传递被重置等与上述交付直接相关的反例；复测范围不无限增长。所有冻结项通过且无BLOCKER_POLICY定义的严重问题时批准W21_SCOPED_APPROVED，不声称整个G5或全平台认证。

## 停止
交付真实代码、必要schema/文档、各case与最佳候选结果、阶段模型/状态及原始证据；修复影响到的W20回归后停止。本轮不进入W22、W23、W24、W25、W26。未授权推送/软件安装/安全策略变更仍按原权限边界处理。
