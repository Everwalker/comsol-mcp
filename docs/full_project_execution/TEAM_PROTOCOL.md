# 主 Agent 开发 → 统一独立 Reviewer → 整改复审

## 开发期
主Agent直接实现、调试、编写和运行自测，并负责资源预算、状态落盘与正常源码同步。独立Developer不是要求。阶段结束保存结果后继续下一个工作包，不等待阶段性签字。涉及模型/数据安全的前置检查照常执行。

主Agent开始时据原文件生成覆盖表，冻结解释和缺省数值基准；不另增产品required条目。可以将明确方案/接口分解为子任务，但这些不扩大原最终范围。科学容差在计算前冻结；修改需有独立理由、新run和版本记录，不覆盖旧失败。

## 统一审查触发
正常路径是在全部实现与主Agent测试候选完成后。若真实外部阻塞使所有剩余任务不可执行，也可要求Reviewer先审可交付部分，并明确总体未完成。不要因为末段暂未写好就请Reviewer不断全局巡检，然后把项目拉回无限审计。

Host必须实际创建独立上下文，记录真实会话标识（不能硬编码/root/reviewer）。Reviewer默认只读生产代码，可以写自己的测量程序/负控并操作独立测试模型。其源码范围、预算和环境权限与主Agent一致，不自动扩大账户或系统权限。

## Reviewer输入与检查
提供MASTER_GOAL、原冻结文件、完整任务/动作/测试映射、候选源码身份与diff、依赖与平台矩阵、原始run索引和待办。不能只提供Main总结。

Reviewer先验证旧证据继承是否适用于最终代码，再检查新增关键实现。自行挑选并运行相关正负控，包括返回候选独立计算、光纤归一化/复场、胶形体积/阶段状态、Desktop目标身份/迁移、公开MCP三入口、错误状态/文件越界、离线源外安装和重开。用例选择受原合同约束；不需重复每个昂贵已批准运行，也不能只运行主Agent保证通过的模板。

结果只有APPROVED、CHANGES_REQUIRED、BLOCKED或SCOPED_REVIEW_WITH_BLOCKERS。SCOPED不代表全项目完成。需要逐项列问题ID、原要求、可复现输入、实际/预期、证据位置、影响、必要修改和复测范围。非阻断建议放backlog，不借建议拒签。

## 循环与快照
主Agent修→提交新的候选→Reviewer独立复测受影响项→关闭具体发现；所有批准绑定被审快照。生产相关字节改变后不自动继承旧签字，文档-only变化可由Reviewer明确豁免原生重算并记录hash桥。

不要让主Agent更改Reviewer结论，也不要让Reviewer自己改产品再自审。没有独立会话能力时REVIEW_BLOCKED；有实现缺陷时继续整改，不能标环境问题。没有最大轮数自动通过；同一根因重复时缩小复现和修设计，不空跑整套报告。

## 有限终点
覆盖原要求、适用测试与交付都完成且没有合格阻断项时，Reviewer必须批准，即使仍有扩展建议。原required缺失、伪观测、错误验证、串模型/串版本、破坏数据或越权必须阻断；未知性能提升、新物理模块或不同产品方向不阻断。
