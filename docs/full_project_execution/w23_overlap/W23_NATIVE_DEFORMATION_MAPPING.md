# W21-to-W23 native deformation mapping adapter

This software unit adds the first concrete W21 deformation-to-W23 optical geometry adapter. It consumes a completed, hash-checked `w21stage` record and the exact W17 `ObservationRef` resolved by the managed project context. It does not accept caller field arrays. The adapter produces a same-model General Extrusion and Prescribed Deformation configuration; it does not call a study or solver.

The current W21 checkpoint schema stores its `ModelRef`, source solution/dataset/study, exact timestamp, field sample, and native outer/inner/solnum mapping. It does not store `project_id` or a revision. The managed operation supplies the immutable project ID and current revision; the observation record's revision must match, and optional duplicated checkpoint values are checked if a later schema adds them. The observation's stored solution identity is canonically hashed and bound to the native readback. Its stored time vector must agree with the selected W21 inner index and timestamp. The Java adapter also checks that the named source solver and dataset exist, that the solver remains associated with the recorded study, and that `getPVals()[inner-1]` equals the selected W21 time.

The frozen expression order is `targetComponent.operator(withsol(sourceSolution,sourceComponent.field,setind(t,inner),outerSelectors))`. The General Extrusion operator is component-scoped to the optical destination, while each displacement field is explicitly qualified to the structural source component. This follows the COMSOL 6.4 Electric Motor Noise example, which moves fields between components and places `withsol` inside `comp.genext`. The source frame is explicitly `material`, the destination frame is `spatial`, the vector basis is global xyz, and `dstmap=[x,y,z]` with `usesrcmap=off` declares the identity coordinate correspondence. A source frame other than material is refused to avoid feeding deformed coordinates back into the map.

Outside-source values are not extrapolated: `method=usetol`, `exttol=0`, `usenan=on`. Native held-out acceptance requires independent source-component point sampling directly from the W21 source dataset and destination-component evaluation through General Extrusion at identical coordinates. A direct source receipt that reuses the coupling operator is rejected. Nonfinite results, including outside-domain NaNs, are rejected. Absolute and relative residual limits must be supplied by a separately frozen native campaign; this implementation does not set thresholds from results.

The preferred route is a persistent Model with General Extrusion plus `withsol`. Native sectionwise export plus a COMSOL Interpolation function remains a later fallback only; it is not implemented as a second active path. This checkpoint does not establish a successful native API readback, numerical mapping, optical solution, 3D mode stability, tolerance scan, capture efficiency, or the full W23 acceptance. Those remain `NOT_RUN`.
