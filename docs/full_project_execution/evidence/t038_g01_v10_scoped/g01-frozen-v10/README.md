# T038 G01 frozen metadata-observer package v4

This v4 successor retains the G01-only observer and one-use Root GO interface. The parent requires hash-bound current manifest, binding, and GO paths; a `GRANTED` scope for this exact source/runtime/output parent/attempt/command; a valid UTC time window; and a fixed 180-second maximum. It creates one `O_EXCL` consume marker under the bound output parent before launching the sole observer child.

After writing and reading back the child stdout/stderr captures, observer report, and parent result, the parent re-reads the same original GO ref, manifest, binding, source members, and every frozen input. It writes and reads back `g01-finalization-revalidation.json` as the pre-finalization-artifact gate, then repeats those input/ref checks. Only then does it check the held output directories and emit final stdout/exit status; it writes no terminal artifact after the last input checks.

The observer obtains production metadata only and never calls `main()` or dispatches a tool. Each emitted input/output schema is checked by installed `jsonschema` and every local `$ref` is resolved through the installed `referencing` registry with retrieval denied. JSON Pointer and anchor refs are supported; ref targets are looked up once rather than recursively expanded, so cycles do not recurse.

The proposed GO file is a schema/example for Root's later decision; it is not a grant. Runtime GO remains `NOT_GRANTED`, and product imports, the observer, and all child launches remain `NOT_RUN`. The external output parent has not been touched.

The v3 one-use invocation failed before attempt-directory creation; no observer child or on-disk consume marker was created. v4 adds only a bounded JSON stderr diagnostic with the caught exception type and message so a future separately authorized preflight can be diagnosed. No retry or new GO is authorized by this bundle.


V5 startup-environment correction: the v4 child capture recorded exactly two unexpected variables, `LC_CTYPE` and `__CF_USER_TEXT_ENCODING`. V5 explicitly sets `LC_CTYPE=C.UTF-8` in the fixed caller/child mapping. At child startup, before exact environment comparison and before any SDK or product import, it records only whether `__CF_USER_TEXT_ENCODING` was present, then removes that one key with `os.environ.pop(key, None)` without reading or recording its value. The exact comparison still rejects every other unexpected, missing, or mismatched variable. V4 remains preserved; this proposal grants no execution authority.
