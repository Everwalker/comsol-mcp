# W25 Desktop service interface and evidence boundary

Status: `SOFTWARE_COORDINATOR_IMPLEMENTED / NATIVE_CONTROL_ADAPTER_NOT_IMPLEMENTED / GUI_TEST_NOT_RUN`.

This document describes the independent Desktop service in `comsol_mcp/_desktop_service.py`. It does not claim the frozen eight-action capability is complete on macOS or Windows. The current Windows and macOS modules only contain read-only window/process identity observers; both report `UNSUPPORTED_CONTROL`. Windows also has a bounded, isolated, lower-level HWND pixel helper, but it is not wired to the Desktop coordinator because it cannot establish a ModelRef binding or publish to a trusted artifact sink. No GUI action, COMSOL launch, COMSOL connection, or native window observation was performed for this work unit. Fixture results are software tests only. See [desktop platform adapter profiles and source evidence](desktop_platform_adapter_matrix.md) for per-action API sources and versioning boundaries.

## Catalog contract

The service accepts exactly the original `desktop.*` operation IDs in `contract/02_ACTION_CATALOG.json`. `desktop.status` is the only read route and requires `READ`. The other seven operations require a caller-supplied `idempotency_key` and `HOST_CONTROL`; `desktop.shell_execute` additionally requires `TRUSTED_CODE`. Permission comes from the host's injected authorization closure. Caller-supplied permission flags are not accepted.

`desktop.status` reports adapter and observed-window state without creating an operation/job. A `window_ref` is minted only from a complete, current adapter observation whose process birth, login identity, desktop session and COMSOL version are present and whose control capability is explicitly `AVAILABLE`. Window title is a display hint only. Leases expire after 30 seconds by default and every write revalidates the same native handle, PID, process birth, login, session and COMSOL version. A restarted coordinator has no old leases or bindings.

`desktop.bind` resolves the catalog model reference through the managed engine queue, inspects it again under the per-window/server-session lock, and compares the observed Desktop server endpoint and model tag with the managed `ModelRef`, including server instance, generation, and the engine's current fingerprint. Every later operation rechecks that same typed reference and fingerprint before acting; a changed fingerprint invalidates the binding. It publishes the in-memory binding only after `OperationStore` records `SUCCEEDED`. Titles, file paths, model tags alone, and caller verification hints cannot establish a binding.

`desktop.show_model` calls the host adapter, then observes the selected Desktop endpoint/model and rechecks the managed `ModelRef`. It reports success only when the platform observation and the server queue agree.

`desktop.select_node` requires an existing verified binding, a nonempty NodePath, and adapter readback of the exact selected path. `desktop.capture` passes through the caller's specific region for the selected window, rejects full-desktop/screen scopes, and requires a result to attest the requested region, target-window scope, artifact ID and SHA-256. `desktop.action` requires a trusted action resolver, adapter verification of the exact action ID, and a post-action window/model cross-check. Every action callback runs while the same native window and server session are serialized.

`desktop.shell_execute` resolves a project artifact with immutable provenance, checks the requested managed model against the live binding, and dispatches only through the injected engine queue. Success requires the queue to attest execution, source SHA-256, and target `ModelRef`, followed by a post-execution binding and fingerprint check. The service does not execute a local shell command. The existing managed-server Java artifact path is not the same as running code in the COMSOL Desktop Java Shell; the native action remains unavailable until a versioned Desktop Shell selector and readback are evidenced.

`desktop.migrate_standalone` accepts only `save_policy={"mode":"save_copy","destination_path":"<absolute new path>","overwrite":false}`. The injected project path policy must authorize the normalized destination. The adapter must return an exact path, SHA-256, and unchanged source dirty/fingerprint evidence; the service hashes the written bytes, loads the copy through the managed queue into the requested session, then rechecks the original window/model and a typed source-preservation record. It does not ask the source Desktop to show the new server model and reports `desktop_binding_verified=false`; the result includes the loaded managed `ModelRef` for an explicit later bind/show operation. The source window/model stays open and its identity, dirty flag, and fingerprint must remain unchanged. It never reports a transparent attach.

## Durable dispatch and queue seam

One `DesktopCoordinator` instance belongs to one control-daemon process and receives the daemon's actual `OperationStore`. For each write, the coordinator calls `OperationStore.begin()` and advances the job to `RUNNING` before any adapter, artifact, filesystem, or engine callback can run. Same-key/same-body terminal calls replay the stored result. Same-key/different-body calls return `IDEMPOTENCY_CONFLICT`. A duplicate seen by the same live coordinator returns `IN_PROGRESS`. Another coordinator that sees `RUNNING` without a local owner record reports `OWNER_UNVERIFIED` and leaves the shared operation/job untouched, because that record may belong to a live process. `QUEUED`, `UNKNOWN`, and `RECONCILING` claims never invoke a callback; this module does not claim to prove remote-owner death or reconcile those jobs. Unknown callback outcomes are stored as `UNKNOWN` with `safe_retry=false`.

Each managed engine callback receives `DesktopDispatchContext`, populated from the durable store claim (`operation_id`, `job_id`, `idempotency_key`, `request_hash`, project and request IDs). The host hook must map the following calls onto the existing serialized engine queue and return its observed result:

| Internal queue operation | Purpose |
|---|---|
| `desktop.binding.resolve` | Resolve a catalog reference to a current typed managed model snapshot. |
| `desktop.binding.inspect` | Recheck the server endpoint, tag, generation and fingerprint for a typed `ModelRef`. |
| `desktop.shell_execute` | Execute a trusted registered artifact against the exact managed model. |
| `model.load` | Load the verified save-copy into the requested managed session. |

Production wiring now instantiates the coordinator from `ControlDaemon` with the daemon's `OperationStore`, the platform metadata adapter, and host-owned permission/action/artifact/path-policy closures. Direct Desktop calls and nested `registry_call`/`operation_call` routes reach this coordinator before the generic daemon claim, preventing a duplicate operation claim. Managed engine callbacks use the existing queue directly and do not recursively call `ControlDaemon.dispatch`. The host's real action, artifact, binding and save-copy providers are not available yet; the integration therefore records deterministic unsupported/validation outcomes with `engine_dispatched=false` instead of simulating native success. See [public control wiring](desktop_control_wiring.md) for the live route and current refusal behavior.

## Per-action implementation status

| Action | Coordinator behavior | Native adapter / acceptance status |
|---|---|---|
| `desktop.status` | Read-only status and identity lease minting | macOS/Windows source observers are present; native observation `NOT_RUN`; metadata adapters currently do not mint handles because controls are unsupported. The status payload includes a versioned capability profile. |
| `desktop.bind` | Durable claim, managed snapshot, Desktop endpoint/tag cross-check, staged binding | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; live GUI binding `NOT_RUN`. |
| `desktop.show_model` | Queue precheck, adapter operation, GUI and queue postcheck | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; `NOT_RUN`. |
| `desktop.select_node` | Verified binding, typed path, exact adapter readback, postcheck | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; `NOT_RUN`. |
| `desktop.capture` | Region allowlist, target-window scope and artifact-hash checks | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; `NOT_RUN`. The isolated Windows HWND helper is a lower-level pixel source only and cannot pass the operation's ModelRef binding or artifact-store requirements. |
| `desktop.action` | Trusted action-plan resolution, exact action readback and binding postcheck | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; `NOT_RUN`. |
| `desktop.shell_execute` | Dual authorization, trusted artifact provenance, exact queue target and result proof | Coordinator has a managed-server Java artifact queue path; that does not satisfy the COMSOL Desktop Java Shell catalog action. Desktop Shell route remains `UNSUPPORTED_CONTROL / NOT_RUN`. |
| `desktop.migrate_standalone` | Save-copy/hash/load/select/source-preservation state machine | `PARTIAL / NOT_IMPLEMENTED_NATIVE_ADAPTER`; `NOT_RUN`. |

The Windows observer uses pywin32 lazily. The macOS observer uses Quartz, psutil and an optional Accessibility trust query without prompting. The Windows pixel helper uses `PrintWindow` only inside a bounded spawned helper process and writes a temporary BMP under a private temporary directory; a timeout stops that helper only and leaves target-window paint completion unknown. Software tests cover the helper protocol with a non-GUI child fixture; they do not invoke Win32 APIs. The factory smoke test selected the host adapter and called its read-only status method; it did not enumerate native windows or invoke Accessibility controls, screen capture, COMSOL, or a GUI action. The Windows process/window observer and macOS window enumeration remain unexecuted. Missing identity fields or permission status fail closed. The user's campaign scope decision to skip macOS Apple Silicon and Intel COMSOL 6.3 remains `USER_REQUESTED_SKIP / NOT_RUN`; this software implementation does not override it or infer compatibility.
