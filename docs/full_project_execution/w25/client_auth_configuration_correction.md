# W25 client authentication configuration correction

The 2026-09-26T22:36Z Java 21 W25 campaign reached the task-owned COMSOL 6.4 server, but client B failed inside `ModelUtil.connect` with the server's username/password error before emitting `CONNECTED`. The immutable receipt is `UNKNOWN`, has no trials, and records zero model operations. Exact server/client identities and stop proof are preserved in [the run reconciliation](../evidence/w25_block_other_clients/campaign_20260926T2235Z/run_20260926T2236Z/cleanup_reconciliation.json); the raw receipt was archived without rewriting it.

The likely configuration mismatch is supported by the current source and same-version API evidence. The isolated runner set `COMSOL_PREFS_DIR` in the child environment but omitted the JVM property used by the production worker. The successful worker launch explicitly includes `-Dcs.prefsdir=<private_prefs>` in [`_java_worker.py`](../../../comsol_mcp/_java_worker.py), and its connection path explicitly passes `encrypted=false` to `ModelUtil.connect`. The installed COMSOL 6.4 Programming Reference Manual, page 43, documents `connect(host, port, encryption)` and states that `false` selects the `ws` WebSocket scheme. The installed 6.4 API JAR also exposes `connect(String, int, boolean)`. This comparison makes the missing task-private JVM preference property the leading authentication cause; it is an inference pending a new native connection.

The frozen candidate therefore makes two narrow changes: `_start_client` now launches Java with `-Dcs.prefsdir` pointing to the same task-owned preferences directory supplied to `mphserver -prefsdir`, and the Java client calls `ModelUtil.connect(host, port, false)`. It does not disable server authentication, access global preferences, read or copy `login.properties`, or log any credential material. The server's `-login auto` behavior remains unchanged.

Offline verification used Python 3.12.13 / pytest 9.1.1: all nine focused runner tests passed. One regression specifically proves that the prelaunch inventory catches both COMSOL's Java `ServerApplication` and `PersistentComsolWorker`, while leaving an unrelated Python service alone. A clean client-runtime preflight compiled both Java sources with Corretto `javac 11.0.31`, then loaded the revised client, COMSOL `ModelUtil`, and `RegistryStrategy` from the installed COMSOL 6.4 plugin classpath using bundled Temurin 21.0.7. It started no server, made no connection, invoked no COMSOL API method, and performed no model operation. Those facts and exact hashes are in the [offline verification receipt](../evidence/w25_block_other_clients/auth_correction_20260926T2252Z/offline_verification.json).

This is a candidate correction, not native authentication proof. Both earlier native receipts remain `UNKNOWN`.
