# W25 private single-claim copy-load software candidate

This isolated Phase2b candidate implements the daemon route admitted by `root-Phase2b-daemon-software-admission001.json`. It adds no public operation, session factory, backend accessor, Coordinator lifecycle change, or model execution ticket. The existing Desktop Coordinator remains the only creator and finisher of the parent operation/job.

The daemon captures catalog-validated migration arguments before that claim, computes the existing canonical request hash, and verifies the actual paired RUNNING operation/job and local owner after claim. Captured values are passed explicitly into the existing session scheduler; ContextVars are not assumed to propagate to its thread. Load requires the exact existing registered project/target session, backend/service/client/Worker object, epoch, lifecycle and health. Missing or retired registered targets never fall back to the legacy backend. Legacy full typed Desktop READ still uses an explicitly captured default backend on `session_scheduler.submit(None, ...)`.

The private callback reads an existing confined, regular non-symlink saved copy and measures hash, size and stat identity before/inside/after queue execution. It performs one fresh unique-tag direct load, verifies the actual returned tag and exact tag delta, binds the verified owned tag, attributes it to the project, persists and independently reads typed session/revision records. It preserves target, foreign and default selected pointers and never restores unexpected drift by assignment. The original saved copy stays intact on failure.

A durable same-job `desktop_copy_load` attempt precedes load. The actual new ref is parent-active before the serialized callback ends. Only the same parent private migration inspect may inspect that provisional ref. The normal daemon execution boundary checks unresolved owned attempts before legacy receiver lookup or pointer selection. New keys, stale clean revision rows, generation aliases, adoption and reopened stores cannot turn an unresolved attempt into a clean ref.

Historical frozen Phase2b preserves the old Coordinator's parent FAILED after a nonmutating binding-inspect exception despite earlier load effects, with a separate NON_READY dirty/active target and safe_retry=false. The fresh Phase2c candidate adds only a local sticky effect marker in the actual parent claim: unchanged ownership checking runs before marking, and a later structured exception or unsuccessful result after that mark records UNKNOWN/safe_retry=false before the existing single finish. Success remains SUCCEEDED; pre-mark refusal retains FAILED/retry semantics. This is a possible-effect classification boundary, not proof of a native effect or a new durable crash/reopen guarantee. Phase2b history, daemon fencing, original engine-call behavior and native limitations remain preserved.

Release requires actual parent and paired job SUCCEEDED, exact captured identity, successful load/source/inspect witnesses and persisted readiness. A release or outer receipt failure retains the original cause and secondary failures separately, re-fences the actual owned ref and returns target NON_READY. An already SUCCEEDED parent remains authoritative and is never overwritten. Same-key replay reads the stored exact target and current durable readiness before exposing success; it does not load, bind or reconcile. Missing admitted provenance is reported as a new incomplete-readiness observation, never reconstructed as historical evidence. If storage cannot preserve a fence, durable guard is explicitly UNVERIFIED, no safe retry is offered, and Root must decide the minimal additional protection.

The integrated daemon also fences final readiness failures within the same `SessionEndpointScheduler` callback. If the provisional-to-READY persist or its readback raises, `_desktop_finalize_owned` re-dirties the exact owned ref and writes the attempt NON_READY before the lane can admit a queued model write. The outer response preserves parent SUCCEEDED versus target NON_READY. A focused adversarial control persists READY, queues a same-lane write during that window, injects an uncertain return, and verifies the queued write is refused before receiver selection. This is software evidence for the integrated source only; it does not establish crash recovery if both durable fence writes fail.

Software tests use real temporary OperationStore, registry/context and scheduler with injected Worker and Desktop protocols. Their request events are synthetic method-entry evidence, not native request termination. All existing Desktop regressions remain required. The source ledger has no global mutex and the parent/ref release is not an atomic database transaction; same-lane admitted write exclusion does not certify arbitrary direct calls or external COMSOL clients.

The original eight actions and T004/T023/T051/T052/T054 acceptance remain OPEN. Actual selectors, shared Desktop/server binding, native unsaved-copy preservation, Shell expected mutation, cancellation, permission recovery and blockOtherClients release require separately authorized actual evidence. No runtime, native, Science, Windows, Intel or complete MASTER acceptance follows from these software fixtures; live source and canonical documents are not promoted by this candidate.
