# 独立审查与验收

## Reviewer 的职责

主 Agent 完成实现与自测后，启动未参与该实现的独立子 Reviewer。先读 RELEASE_DOD.md、目标矩阵、当前候选身份、任务索引和必要原始证据，逐组评估 U01–U12。真实工具不可用则不得假装已分配或已接受。必要的早期技术咨询可以做，但不把每个片段的子审签升级为额外发布关卡。

一次审查覆盖：实际 actions/API 目录与原测试子断言映射、通用能力是否依赖核心硬编码、模型/项目绑定、文件/产物授权、结果/解身份、真实取消/UNKNOWN、恢复/分发、所有适用目标。分别记录执行状态、数值核验、物理验证。使用适量正控及已发现风险的负控，不要求枚举所有未来物理与操作系统故障。

## 两族未预设迁移

候选冻结后，由 Reviewer 选择两个小任务族，至少一个涉及非旧案例的物理接口或通用方程，至少一个陌生已有模型；固定任务规模与有限判断标准。Windows COMSOL 6.3、6.4 各执行两族，共四个组合。只能用正常安装 MCP 和项目级代码完成；若需要改服务端，先按通用缺陷修复，再冻结并使用同难度变体复测。不能为每题写服务端特例后声称通用。

## 问题分级与收口

- 阻断：冻结合同缺失、结果/权限/身份不可信、真实数据损坏、泛化依赖核心特例、证据与当前候选不符、必需平台未验证。
- 非阻断：合同外更大模型、额外物理 recipe、更多可选平台或性能优化。进入待办，不能无限扩张本轮验收。
- 主 Agent 修复阻断问题；Reviewer 复核改变的范围及受影响链路。未改变的已接受事实可继承，不因文档或无关源码哈希变化重做全矩阵。
- REVIEW 记录 reviewer 实际身份、候选、范围、结论、证据与剩余问题。主 Agent 不能自签替代独立审查，也不能将本工作包审查当产品验收。

只有完整适用范围达到合同、原始证据可复核且 Reviewer 批准，才交付 UNIVERSAL_CORE_VERIFIED_SCOPED。若只剩外部真实阻塞，则交付 WAITING_EXTERNAL 和最小解阻清单，不用 NOT_APPLICABLE 或 IMPLEMENTED 伪装通过。
