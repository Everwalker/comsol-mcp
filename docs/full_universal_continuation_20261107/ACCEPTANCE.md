# 有限验收与独立终审

## 原合同是唯一完成边界

`RELEASE_DOD.md` / `config/UNIVERSAL_DOD.json` 原样保存 U01–U12。
本包 TASKS 的细分只帮助执行。它不增加平台、不要求每个子步骤独立审批，也不要求所有底层 API 都有专用 wrapper。

| 证据层 | 可以说明 | 不能代替 |
|---|---|---|
| 软件测试/假 Worker | 协议、边界、类型、状态与负控的指定行为 | 真实 COMSOL 运行、许可证、安装 |
| 真 SDK + JDK 编译 | 该 SDK/build/JDK 的编译兼容性 | Worker 启动、原生求解、Windows 句柄 |
| 已安装 MCP | 源目录之外的真实公开入口和工具响应 | 尚未实际运行的其余工具 |
| 原生执行/结果/重开 | 指定版本、模型、解、平台的实际行为 | 所有物理问题科学正确 |
| 独立数值/物理验证 | 指定观测/profile 的数值/物理结论 | 不在 profile 内的结论 |

## 有限检查

- 按变化影响范围选择精确测试节点和实际小任务。已接受的 Java 软件基线可复用；`config/test_selection.json` 提供有限节点，默认脚本只打印，不自动启动。
- 参数化用例数可以与节点数不同；重跑/重叠套件不相加为一个“总通过”。
- `tests/test_java_worker.py` 包含会启动真实 Worker 的 fixture；不要用整个模块或广泛 `-k` 替代明确选择。Native 用例须先确认现场资源、模型/Server 所有权。
- 文档变化不自动失效所有 native 证据；生产代码/构件变化按可证明的影响范围失效和补验。记录复用理由，不能偷换构件身份。
- 不重试没有修复原因或环境变化的已知失败；无阻塞的任务先推进。

## 正式 heldout

在最终候选身份冻结之后，由独立 Reviewer 选择**两个小型任务家族**：
1. 至少一个使用非旧案例物理接口或通用方程；
2. 至少一个是 Reviewer 提供/选取的陌生已有模型任务。

两类分别在 Windows 6.3 与 6.4 的已安装 MCP 入口完成，含真实结果与有限负控；不得修改服务端以适配题目，项目内 Java/参数/模型操作是允许的通用路线。两类实验只给有限迁移证据，须结合架构与接口覆盖审查。

失败若需修改服务端，修复后重新冻结候选，对受影响家族用同难度新变体复测；通过且不受影响的结论不无理由重做。不能把第三、第四类新题不断加入 required。

## 全局覆盖表

最终覆盖表逐项映射：
- 当前实际 action/工具目录；
- 原设计中的测试用例及子断言；
- U01–U12；
- 真实可用执行路径（wrapper/API/项目 Java）、适用平台/版本和证据范围。

历史数字 273 动作、60 用例、427 子断言，以及 synthetic metadata 项可能造成的目录计数差异，只是定位提示。以恢复后实际目录为准，解释新增/移除/合并，不以数字凑齐充当覆盖。一个路由可以覆盖多个动作，不要求无意义重复跑；标 PASS 必须有适用证据，列出名称不等于运行过。

## 最终 Reviewer 报告

Reviewer 报告至少包含：
- 主 Agent 与独立 Reviewer 身份/会话；真实审查日期；
- 候选源码 commit/tree、构件 hash、目标平台和实际测试入口；
- U01–U12 的判定及证据路径，未运行/跳过/不适用的精确理由；
- 自选反例与 heldout 的输入、可复现步骤、实际结果和限制；
- 每个问题的级别、受影响条款、是否阻断、修复/复核状态；
- `ACCEPT` / `CHANGES_REQUIRED` / `BLOCKED` 结论和范围。

主 Agent 修复阻断项后交同一 Reviewer 复核受影响范围。所有 applicable required 满足后，统一宣布 `UNIVERSAL_CORE_VERIFIED_SCOPED`；不能用本工作包的检查报告代替产品审查。

## 交付与外部写入

本用户已要求开发、修复、测试和交付准备，可持续执行这些工作。创建可审查分支/提交和完整交付目录，不需要每小步再请求授权。远端发布/合并/发行依当前会话已有授权与仓库保护规则执行；若确需最终授权，先准备完可审查候选、构件及独立结论，再一次性请求。不得用历史“每阶段 push main”自动覆盖受保护分支或绕过审批。候选技术验收与尚待授权的发布动作分别记录。
