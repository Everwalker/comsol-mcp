# 52 项执行任务：完成全部既定通用范围

本表由 `TASKS.json` 的同一任务数据生成。10 组、52 步；依赖用于推进，不新增 52 个审签门槛。原合同仍为 `RELEASE_DOD.md` 的 U01–U12。

## 如何使用依赖

- 优先 T01/T02 后打通 T05–T09 的正常安装真实闭环；T03/T04、通用代码、作业和构件准备同步推进。
- `depends_on` 指相关实现/接口准备。前驱 `implementation_done=true` 时，下游软件工作可先做，即使前驱原生验证被外部阻塞。任务 DONE 则必须有本行验收证据。
- `status=BLOCKED` 且 `implementation_done=true` 表示实现已完成、验证仍等待；不能写成 PASS。各 native target 检查分别记录，Mac 不等 Windows，Windows heldout 不等 Mac 整矩阵。
- T47 冻结候选，要求生产实现、T43 两个 Windows 正常安装行和 T46 两个 Windows 核心原生行齐备；两类正式题目此后由 Reviewer 选择。Mac/生命周期/Desktop 的剩余验收不阻止先做 heldout，但 T50–T52 必须补齐全部适用验证。
- T48 产生真实结果（包括失败）后记 execution_complete=true 并引用证据，即可进入 T49；T48 失败仍保持未验收，不用先通过才能修复。修复/重冻/等价变体通过后才关闭相应验收。
- 每组复用一份证据 bundle 即可，每项引用必要产物。无需为每个文件或命令建立审签记录。
