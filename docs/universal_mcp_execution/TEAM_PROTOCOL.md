# 主Agent开发，独立子Reviewer最终验收

角色：主Agent直接实现/调试/自测/集成/调度，不需要Developer子Agent。Reviewer由宿主实际创建独立上下文，自己读取当前候选、冻结范围和原始记录；不是同一会话换角色标题。
开发期不为每个setter/小补丁创建新审批包。必要权限和危险操作门禁照常，阶段完成继续。Reviewer在候选完成后统一检查required覆盖、关键安全/类型/数据/恢复反例，并选择冻结候选未预设的两类任务。

Reviewer对每项给APPROVED/CHANGES_REQUIRED/BLOCKED及具体证据/可复现问题。仅所需证据不足、实际缺陷或明确严重风险可阻断；新的非required建议入BACKLOG。不能要求全模块科学校准、无限测试或每条Java API逐一手写wrapper才能通过。
主Agent修复后冻结新候选，只重测受影响范围和必要泛化反例。Reviewer不能在没有运行时写“实测通过”；也不能因不会运行某机器，直接把整项自动判正确。

独立会话ID和源码候选hash是审计索引，不是密码学独立性证明；不要再造一套签字验证系统。记录宿主实际会话和原始命令/结果，Reviewer必须自己做工作。宿主无独立会话能力则留下REVIEW_BLOCKED，不能主Agent自签。

结束：冻结required全部达到适用范围、通用冷启动和两题迁移验证通过后必须给明确批准。历史未完成的可选科学任务不因此转PASS；保留它们的状态，不阻止通用核心发布。审批后再改核心代码，相关批准失效，定向复审。
