# 本轮明确的范围变更（用户决定，不伪称原设计已如此完成）

## 保持的原目标
面向云端强模型的通用、可观察、可编程、可恢复的COMSOL操作环境。保留领域工具、通用对象/API、MCP内受控Java、实际结果与图像、持久作业、安全模型身份、可选Desktop和跨平台交付。许可证/平台/权限/API/资源与物理假设边界必须如实报告。

## 本轮变更
1. 产品成功标准从“逐一完成原三类科学项目”改为“在已声明支持及合法授权范围内，新任务可用现有MCP接口和项目级代码完成，不需改MCP服务端源码、硬编码任务变量或增补固定任务白名单”。
2. W22–W24中的通用能力仍required；其具体光斑、光纤设计、胶形稳定、UV/固化本构校准和工艺科学终点归为可选recipe/专项状态，不再阻塞通用核心发布。不删除源代码/案例/旧测试，不给未完成科学项写PASS。
3. W20的一般验证机制、三层状态和W21的一般扫描/预算/状态映射仍required；不要求系统内置所有物理学正确性判据。未知物理规则应NOT_COVERED，不能全PASS，也不能因此拒绝所有求值。
4. W26的数据/模型/依赖完整恢复仍required；“三领域全科学重放”改成一般项目及本轮泛化任务的完整重放。案例的历史交付状态单列。
5. 不机械按W01→W26逐阶段停工。沿原逻辑动作目录建立一次覆盖映射，实际JSON计数为准；已读固定目录声明273项，不沿用历史272常数，也不把动作数当可执行完成率。
6. 完成范围按 RELEASE_DOD.md 的12组通用标准冻结。原60测试保留，逐子断言标明继承/受影响重测/案例专项/既有用户跳过；不能把案例专项名称下的模型身份、原生结果、文件安全等通用义务一起延期。
7. 主Agent持续开发、自测；独立Reviewer最终统一验收。新非关键建议进BACKLOG，不每轮重开全部基线。真正会引起模型错误操作、错误科学认证、数据丢失、越权或核心不可执行的问题仍阻断。

## 既有平台决定
Windows x64×6.3、Windows x64×6.4、macOS Apple Silicon×6.4为当前活跃原生目标。最新交接明确macOS ARM/Intel×6.3原生以及Intel Mac×6.4硬件为USER_REQUESTED_SKIP；保持它们的精确范围，不写PASS。三架构构件构建/依赖和静态兼容责任不因此自动取消。当前不能访问某个活跃环境时完成其余工作，记录该目标BLOCKED；不能声称全矩阵验收完成。
