# 实施方向：能力与任务分离

## 三层布局（可按现有模块职责实现，不要求改目录大搬家）
核心：运行时/版本、模型身份、typed对象、API元数据/调用、受控代码、事务/队列/结果/产物/恢复/安全。
recipe：可选择的领域知识、模型构建脚本、参数、物理假设和验证profile。可使用任意用户项目目录中的合法recipe，不要求先打进产品发行包。
测试：固定/变异/未预设任务及独立解析参考。它们检验核心，但变量名、tag、数值oracle和Activity/R编号不能反向定义核心权限。

去掉三个案例recipe和测试资源时，核心仍能安装启动、读写其他模型。保留recipe的历史科学状态；不要靠隐藏失败测试制造通过。

## 调用与发现
采用“优先领域动作→通用对象/API→MCP内受控Java”的路由，三条都必须绑定同一ModelRef/epoch/revision并经过同样的权限、队列、作业与产物系统。
通用API的受审范围不能长期只剩comments两个方法。以实际接口/签名/类型/版本元数据及经过验证的副作用分类管理操作，不以模型标签/表达式名字白名单管理权限。旧node.remove的受限行为保留准确说明，在原授权范围内补充通用对象族安全删除/回读；不盲目cascade。
安全效应不能只听调用者declared_effect；反射查到方法也不等于已证明只读。未知方法可解释拒绝，但必须给出在原能力范围内可用的受控代码路径；不能为了新任务要求再修改Worker核心允许名单。
Java路径须允许Agent在项目内创建新的源码、编译和执行于当前模型，并返回编译诊断、运行异常、写后回读、partial/UNKNOWN状态。项目级源码/recipe不是服务端源码修改。不能将任意Java称作OS沙箱：trusted_code须明确授权，必要时采用真正隔离的Worker/进程、受控主机权限和原所有权保护。

## 真实自省而非任务专用调查脚本
公开属性清单、实际类型、允许值、单位、数组形状、组件/几何/物理/Study/Solver关系和版本化帮助。优先使用实际对象与官方API，不把feature type字符串的Java编译通过当成该对象支持该属性。
真实返回完整布尔、向量、矩阵、复数和轴元数据；维度/时间/频率/outer/inner无法证明就明确缺口，不猜第一项。未知新物理接口可通过通用路径实现，并在能力表标明由哪条路径完成及当前验证范围。
默认单位由表达式求值上下文及引擎回读决定，不把emw.*四个表达式的特例当整个产品默认单位契约。显式单位/默认单位模式区分，不能默默更改数值。

## 授权与恢复简化
一次授权覆盖明确项目、模型/运行时、操作类别、计算/文件预算和失效条件；在范围内批量setter不逐次人工审批。扩大主机访问、删除、对共享Server停止等才另外授权。禁止放宽隔离来“变通用”。
用现有OperationStore/idempotency/job/revision/checkpoint作一套状态真源；未知活动冻结冲突资源、允许独立资源继续。历史once/原Popen是旧活动证据，不是新项目永久前置；不能伪造旧句柄接管，也不能因此禁止新隔离项目正常建立。
日志支持有界内存、分页/轮转/流式证据和终态预留，不为每个更长案例继续提高常量上限就宣布解决。trace/logger失败与引擎失败分开，关键终态不可静默丢弃。

## 交付
一套规范公共源码和清晰候选集成差异。原未合并候选逐逻辑合并通用修复，不能整目录互盖。一个官方安装入口、配置schema、版本capability、离线构件与升级/回退；普通使用不需要旧_activity文件夹、固定source-lock审批或仓库测试driver。
GUI是API无法完成操作的可选适配，不取代一般模型API；使用共享连接或明确迁移路径，不宣称能从任意独立Desktop内存无条件接管。无权限/能力时清楚说明并保留API工作流。
