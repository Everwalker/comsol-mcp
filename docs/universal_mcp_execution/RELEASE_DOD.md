## 证据与目标
- 当前原生目标：Windows x64 6.3/6.4、macOS ARM 6.4。每个原生目标有真实运行记录；软件单测/编译/假引擎只支持其本身范围，不升格原生。
- 已有明确用户跳过的三项按config/TARGETS保留，不要求重新取得这些机器；构件构建责任保持。缺少其他活跃目标则交付准确BLOCKED，不声称全部通过。
- 正常公开入口、ModelRef、运行时实际build和真实解/产物身份要对应。少量独立解析基准可验证通用运算，不要求W23/W24复杂科学收敛作为本合同前提。
- 每一组由主Agent记录实际实现与原始测试，Reviewer逐组判断。原action目录每项映射至少一条实际执行路径及证据范围；无专用wrapper不等于失败，有受控Java也不等于默认全部PASS。
- U11是候选冻结后的有限实验，不另建大规模基准平台。只有实际修改服务端才能完成时，该候选未满足迁移要求；修复后重新冻结并用同难度变体复测。

## 状态和终点
只有required和适用目标满足、独立Reviewer批准才能写UNIVERSAL_CORE_VERIFIED_SCOPED。批准依赖当前源码和构件；变更后针对影响范围复审。
BLOCKED、NOT_RUN、UNVERIFIED不转换为PASS。NOT_APPLICABLE要具体说明适用范围，不能用来逃避承诺核心功能。
移除核心安全/权限、硬编码任务答案、将外部值伪装引擎结果、用旧图/旧解冒充新结果、未实际停止却写cancelled等属于阻断。
性能改善、更多物理recipe、更大模型和未要求平台进入待办；核心合格后必须给出阶段关闭，不要求待办清零。原三案例专项缺口不影响通用核心批准，但绝不可说它们已完成。
