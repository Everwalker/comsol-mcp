## 缺口 2：检索计分误命中（已证实，最小修复）

复核发现：修复前 `search` 只要**任一** token 命中（`relevance > 0`）就发布，短子串如 `be`（匹配 describe/before）也计分。probe 首跑中 `docs.search('file cannot be read', node_type=ModelUtil)` 的展示前两名是 `comsol_api_intro.46.08/13.html`（Java 模型文件/Eclipse 介绍页），其正文并不含该错误短语——当时标 `SUCCEEDED` 不能证明找到该错误或其解释。对索引库的直接核对：

```text
exact phrase 'file cannot be read' chunks:
  api/com/comsol/model/util/ModelUtil.html offset 11959 / 17820 / 23745
comsol_api_intro.46.08.html: cannot? False  exact? False      # 首跑误命中
```

修复（通用语义，不按该样例硬编码）：发布改为 **AND token 语义** —— 文档（title 或 content）必须包含全部查询 token 才进入结果（`coverage = len(terms)` 谓词），相关性仍按 title>content 排序；部分 token 命中的页面不再发布。粒度说明：AND 按 chunk 内的 token 存在性，不是连续短语匹配；短语级证据由 `docs.get(section=短语)` 的分段取回证明（见 transcript F）。

定向测试：`test_multi_token_query_publishes_only_documents_holding_every_term`（共享部分 token 的页面被排除；完整短语命中含短语页；缺任一 token 整片 NOT_FOUND；短共享查询合法返回两页）。
