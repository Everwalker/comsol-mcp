## 6. trusted Java 的实际主机权限（如实）

- 部署 opt-in：`COMSOL_MCP_TRUSTED_CODE=1` 在 ManagedBackend 构造时捕获为 `host_permission_ceiling`，一个 backend 生命周期内环境变化不能扩大或撤销（需重启）；`host_control` 是独立 opt-in。
- 连接成功从不隐含授予：每次 Worker 连接先 discard 再按 ceiling 重放 trusted_code/host_control；成功连接从不隐含 license checkout。
- 项目 gate 之下没有 OS 沙箱（关键如实项）：trusted Java 在常驻 Worker JVM 内编译执行，权限等同 daemon/Worker 的同一 OS 用户 —— 可读写该用户可达的文件、可发起网络连接。项目 workspace 绑定、java-source 512 KiB 上限、artifact sha256/pinned-handle、recipe witness 与 durable 票据约束的是控制面身份与可审计性，不能替代进程隔离。Windows T037-bound 路线额外要求原生 policy 观测验证（`_require_t037_policy`），未验证时拒绝。
- 实际主机执行证据仅限 T06/T17 的 macOS arm64 6.4.0.293 单一独立项目；Windows x64 与 COMSOL 6.3 的 trusted Java 主机行为 UNVERIFIED。
