# 主任务：一次性完成通用 COMSOL MCP，然后独立统一验收

## 0. 当前任务优先级与终点
以用户最新定位为准：构建面向云端强模型的全能通用MCP，而不是三种固定科学项目的自动化程序。**新任务只能需要任务定义、参数、模型或项目级代码，不应需要修改MCP核心、增加任务专用白名单或重新制作产品安装包。**“全能”限于合法许可证、公开API/已支持Desktop、平台和授权资源；不承诺突破COMSOL本身或自动保证未知物理正确。

按SCOPE_RESET.md明确更新完成范围，保留旧证据和已有接受结果。普通通用能力、平台适配、恢复、安全与发布仍完整交付；三类案例科学终点不再阻塞通用核心。不要以降级字段、把FAIL写成SKIP、改原始报告来实现范围变更。

主Agent直接设计、实现、测试和集成，持续完成全部required核心范围，最后由真正独立的Reviewer统一验收并整改复审。无需Developer子Agent，不逐阶段等待用户重新发送Goal。任何阶段摘要、源码同步、包生成或某个case通过都不是本轮终点。

## 3. 核心实现（连续推进）
### M1 通用对象、自省和版本能力
按ARCHITECTURE补node.*、api.describe/invoke、实际对象元数据与本地版本文档。接口不局限注释两方法或单一6.4.0.293。建立接口/签名/类型与effect能力策略及6.3/6.4适配；不通过移除所有允许策略来“开放”。
常规节点结构操作、安全的明确对象删除、嵌套WorkPlane/feature、选择、材料、物理、mesh/Study/Solver都可经至少一条受管路径完成。真实不支持则明确原因和替代，不以未写专用按钮永久拒绝本可执行的任务。
所有名称/tag/component/geometry/dataset/表达式/单位是任务输入或实际回读。测试换名、增加组件、更换路径/单位仍能工作；修复从领域任务发现的问题时，默认寻找公共语义而不是写该任务特判。

### M2 通用受控代码与工程执行闭环
确保普通安装的MCP接受项目内新Java源码，绑定指定现有模型，完成编译/运行/错误/回读/产物，不另启绕过MCP的引擎。没有wrapper也能创建新physics feature和完成一次求解；调用未知方法的元数据、文档、实际版本验证与权限路径清楚。
一次授权允许在项目范围批量执行；按现有job队列、revision、checkpoint、timeout/reconcile机制工作。主Agent必须在开发过程中经公开入口自测，而不是最后才发现stub签名和schema不一致。
用户已有模型是首要使用方式之一：连接/加载/采用现有模型、只修改目标、保留其他模型/结果/自定义节点；共享Desktop不能猜窗口，迁移有保存和归属前提。自动参数扫描/优化复用真实case执行，不内置某种温度/胶/光纤公式冒充通用目标函数。

### M3 真实结果、图像、验证和恢复
完整保留数值类型、维度/时间/频率/参数解、复场、单位/坐标/测度；求值临时节点只清理本次对象。跨物理量指标定义由任务配置，物理层未知不妨碍返回真实原始值。
图像由真实COMSOL渲染，经MCP图像或实际资源能力传给Host，带模型/解/参数/单位身份；不只返回本地路径。文件授权、登记和默认不覆盖规则统一。
验证数据必须来自同模型同解的后端观测或明确外部数据模式。执行/数值/物理状态分开；不承诺判断任意未覆盖物理假设。报告写入使用同一ArtifactStore，缺数据/清理失败/状态未知不能成功认证。
长作业状态独立响应，Host失联/控制重启查原job不重放；真正支持的取消与仅请求取消分开。无可信所有权拒绝强停，不能误杀其他用户模型或另一版本。
持久保存模型、依赖、报告与公开产物；新目录/新Worker同版本重新打开并读存储解。不同版本格式限制如实说明，不承诺6.4→6.3无损保存。

### M4 安装与正常使用
把候选通用修复放入一份规范源码与正常构件。不同OS/arch/JDK/COMSOL的配置和版本差异集中，不硬编码用户名/安装目录/活动哈希。离线安装、升级回退、卸载数据保护与普通启动继续完成；开发时联网不取消产品离线能力。
平台范围见config/TARGETS.json。Windows 6.3/6.4和macOS ARM6.4逐个实际验证；既有用户跳过保持SKIP不是PASS。某活跃机器当前不可访问时完成软件/构件和其他目标，标明剩余外部阻塞，不能宣称全目标通过。

## 4. 未预设任务证明：不是再加三个长期科学项目
到候选可用后冻结生产代码，由独立Reviewer从实际许可支持的接口中选择两个小型、可确定判断的任务族（不可都只是同一铜块改参数），至少一个涉及非既有案例的物理接口或通用方程，至少一个从陌生已有模型开始修改。每题包含明确输入、有限预算、可核验输出和负控。两题先在Windows两版跑，同一合同不要不断增加题目；MacARM6.4做适用核心链回归。
主Agent只使用已安装MCP、官方文档和项目级代码/recipe执行。允许编写新任务Java、换参数和输入模型；不允许改MCP包、Worker协议、核心允许策略、内置任务库或安装文件。出现真实核心bug可以修，但该候选失效，修后Reviewer用同难度等价任务复测，不把刚硬编码的答案当泛化成功。
目标不是让Agent解决开放科学难题，而是证明现有执行环境能承载新合法任务。结果必须有真实操作/产物；COMSOL模块许可缺失或模型本身物理不可定，应准确归因而非加专用绕过。

## 5. 独立统一审查，不把日常工作变成审批工程
遵循TEAM_PROTOCOL。开发期主Agent持续自测、集成；最终候选就绪再启独立Reviewer。Reviewer在独立上下文读原目标、本包scope、当前代码及原始证据，自己执行关键负控和两题迁移测试，不只复述主Agent总结。
Reviewer可以拒绝未满足冻结required或有直接证据的严重风险；不能把新功能、美化、无限物理校准和未约定平台升级为本轮门槛。非阻断发现进BACKLOG，批准不要求待办清空。
宿主不能创建独立子会话时如实记录REVIEW_BLOCKED；先完成可做工作，不用同一Agent自称“独立Reviewer”。代码变动使受影响批准失效，只复审其影响，不每次从头扩大全仓审计。

## 6. 持续执行、完成与真实阻塞
每个安全里程碑更新唯一state/RESUME.json，记录实际工作树、next_action、活job引用和阻塞，不保存token/有效审批。会话重启读指针并核实实际job再继续；同一个Goal可续跑，但不声称无宿主触发也能后台重启。
普通阶段完成、包生成、sync请求都不是停点。相同环境/许可阻塞记一次后转可独立任务，不能无限重复check-only。旧科学活动UNKNOWN不应冻结另一份授权独立项目。
完成标准是RELEASE_DOD中全部required通用义务与适用目标有真实依据，目录可重建、独立Reviewer批准、能力与限制如实交付。发布名可用UNIVERSAL_CORE_VERIFIED_SCOPED，不用“所有物理/所有OS无限认证”。三个案例未完不阻塞此结论，但专项状态仍公开列出。
未完成required或独立审查缺失时只能IMPLEMENTED_WITH_BLOCKERS，不伪报全部完成。正常commit/push遵循用户既有明确权限，无权限时交付patch/bundle并记录待同步；不force、不上传私人科学模型/秘密。
