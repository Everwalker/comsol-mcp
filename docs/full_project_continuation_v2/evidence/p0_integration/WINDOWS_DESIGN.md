# Windows publication implementation

Source: `comsol_mcp/_windows_parameter_publish.py`, stdlib-only, no MCP imports. The handle-relative calls follow Microsoft's [OBJECT_ATTRIBUTES](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes), [NtCreateFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info), and [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle) documentation.

- Open each lexical directory child relative to the already-pinned parent HANDLE with `NtCreateFile`, `OBJ_DONT_REPARSE`, and `FILE_OPEN_REPARSE_POINT`; reject reparse objects and require named-path identity to match. The drive root is admitted first, and directory handles omit DELETE sharing. Preserve production ArtifactStore protected/private path policy in the adapter.
- Create the random temporary leaf relative to the pinned final parent handle with `FILE_CREATE`, `FILE_NON_DIRECTORY_FILE`, `FILE_SYNCHRONOUS_IO_NONALERT`, and `FILE_OPEN_REPARSE_POINT`. It has READ/WRITE/DELETE access and READ-only sharing. `publish_chunks` writes bounded chunks to this same handle, verifies the expected SHA-256 and exact size before commit, flushes, then renames the same owned handle relative to the pinned parent with ReplaceIfExists=false. `publish(bytes)` remains the small-payload compatibility entrypoint. ctypes defines the native OBJECT_ATTRIBUTES/UNICODE_STRING layouts, flag union, HANDLE alignment and UTF-16 byte length.
- ArtifactStore's internal `publish_project_file_no_clobber` pins an owned source inside the trusted project and supplies a one-pass reader; Windows opens that source relative to its pinned parent and rechecks source metadata plus named parent binding when the iterator ends, before the destination rename. The Windows publisher receives only the iterator, expected hash, and expected size; it never receives a source pathname.
- A pre-existing directory handle with `FILE_WRITE_ATTRIBUTES` may issue `FSCTL_SET_REPARSE_POINT`; share modes do not revoke access already granted to that handle. Microsoft's [MS-FSA rule](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/4aeefef8-92c3-4abc-af7a-a610caf8a165) admits `FILE_WRITE_ATTRIBUTES` for this operation. Native coverage injects a directory junction after pinning and before `NtCreateFile`, records every actual temp handle path before writing, then verifies typed refusal or that any write stayed in the pinned directory; the outside directory must remain empty.
- Verify identity and SHA/size through the same handle, flush again. Success reports file-flush/readback scope; no directory power-loss guarantee is inferred.
- Failure cleanup marks only the owned handle for deletion, then closes and checks absence. Reader, Win32 and cleanup exceptions keep the original stage/cause and become ARTIFACT_PUBLISH_UNKNOWN whenever an owned residual cannot be verified absent. Preexisting destinations are preserved. Production wrapper converts constant-detail PublishError to ExecutionContractError.
- Ordinary absolute drive roots only, bounded length; reject UNC/device namespaces, ADS, traversal, reserved names, short-name aliases, trailing dot/space. Ordinary Unicode/spaces remain valid. Native tests must run on Windows; Darwin lexical controls cannot establish Windows kernel/filesystem behavior.

Main Agent reviews and may transfer exactly the frozen helper/test files to the authorized Windows scratch after a read-only target preflight. The current Mac host cannot reach that Windows address, so its native run remains NOT_RUN. This unit does not start COMSOL or claim Windows/native acceptance.
