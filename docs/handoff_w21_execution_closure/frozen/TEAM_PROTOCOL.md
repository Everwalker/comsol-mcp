# 主Agent开发 + 一个独立Reviewer

主Agent负责计划、实现、调试、测试、交付和调度，不创建独立Developer。Reviewer必须是Host实际创建的另一个上下文，自己读冻结判据、候选源码及原始证据，自己构造并执行范围内必要反例。角色称呼、JSON中的不同ID或文件hash不证明独立执行。

## 流程
1. 主Agent核对已有16项/27目标，仅建立现状映射；Reviewer确认范围没有增长，不增加新毕业条件。
2. 主Agent按差距实现，提交候选与实际回归结果。
3. Reviewer按冻结标准做独立复测，用BLOCKER_POLICY区分必须修复与延期。只看报告器是否通过不够。
4. 有A1/A2：返回具体CHANGES_REQUIRED；主Agent修复并出新候选；Reviewer复测改变与受影响部分。
5. 原标准满足且无阻断：Reviewer给W20_APPROVED；主Agent直接转W21。
6. W21同样开发/独立复核，完成后停止。没有第三层reviewer-of-reviewer。

## 复测和证据复用
审查全部目标不等于每轮重算全部模型。已有证据的源范围及运行条件未受影响即可复用，记录理由；关键新行为和原合同规定的独立负控仍须实际复测。源码和依赖变更影响到的条目重新验证，不自动继承批准；纯进度文档或非相关文件变化不无条件推翻已有验证。

## 防止空转
同一缺陷两轮未解决时拆成小复现，诊断架构/因果，不再重复整个runner。没有总轮数自动批准规则；也没有强制“每一轮必须再找新问题”。不创建新的审查门禁软件作为当前阶段前置。

## Host与执行隔离
Host无法建立独立子会话时，准确标REVIEW_BLOCKED，主Agent继续不依赖审查的开发，不代签。需要人工/管理员/许可的动作按原权限处理。独立Reviewer可用独立测试项目或预约同一测试Server时段；同一模型不能并行写入，不能使用用户真实未保存模型作破坏性负控。

现有会话定位和原始测试日志足够，按宿主实际提供方式保存；无需为证明独立性建设新的身份平台。Reviewer不改生产代码后自我批准，建议修补交主Agent实施。
