# W20 收口 → W21｜停止移动验收目标

本包替换上一份工作包的**推进和审查方式**，不是新的全仓审计结论。采用同一个公开源码起点；没有重新检查 main，没有宣称旧问题已经修复。

## 使用
在 Windows 新目录解压，使用 Agent 打开整个包根目录，发送 GOAL.txt。主 Agent 直接开发，不需要独立 Developer；独立子 Reviewer 负责复核。用户已明确安装 COMSOL 6.3/6.4，两版本按冻结要求分别执行。

包是**联网恢复型，不是离线源码镜像**。tools/bootstrap.py 会从 PIN.json 的固定公开提交恢复全部受支持的已提交内容并核对 Git tree。它不读取旧项目、旧聊天或旧运行状态，也不安装/启动 COMSOL。

## 这次固定什么
- contract/W20_ACCEPTANCE.json、W20_ACCEPTANCE.md、W20_BENCHMARKS.md 是原 G3.11 文件的字节级副本：仍然 16 项、27 个目标，不删条目、不改数值容差、不用 mock 替换原生证据。
- 原 JSON 中 stage/stop_before 属于历史标识；本用户任务明确将旧“W20后停止”改为“W20批准后直接进入W21，W21后停止”。这是推进规则变化，不是行为标准变化。
- T16 所称“本轮P0/P1”由 BLOCKER_POLICY.md 按影响和证据判定，不等于任何被标P1的建议都能阻止毕业。
- 不再重新全仓找新问题、不增加 Reviewer 层级或新的证明系统。既有日志/测试/源码快照可以复用，按影响范围补测。

## 真正的终点
W20全部既定目标通过且无合格阻断项，独立 Reviewer 必须给当前候选 W20_APPROVED；非阻断改进不能成为拒签理由。主 Agent 随即按 W21_PLAN.md 执行原 W21 的通用部分，完成后停止，不自动开始 W22。

缺环境/许可证/独立Reviewer、真实测试未跑或证据不足时仍不能报完成。冻结目标不是容许错误结果、串模型、破坏数据或越权。

## 文件地图
NEXT_GOAL.md 是唯一当前任务；BLOCKER_POLICY.md 规定什么能阻断；TEAM_PROTOCOL.md 规定双角色流程；W21_PLAN.md 规定批准后的下一部分。PROGRESS.md 与 DEFERRED_BACKLOG.md 为运行中的两份简短记录，无需再造并行台账。

清理旧目录前保留商业软件安装、许可证、未提交实验数据、唯一MPH与未保存模型。先验证新目录可恢复，再删除旧项目更稳妥。
